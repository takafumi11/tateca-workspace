# Tateca — プロダクト概要

PdM・Biz・エンジニア・AI エージェントが、Tateca が何をするプロダクトかを最初に把握するための文書。
機能ごとの要件と受け入れ基準（AC）は `requirements/` にある。

## Tateca とは

旅行・食事・イベントなど、日常の割り勘シーンで発生する共有費用を管理するアプリ。
複数のユーザーが共有するグループの中で、立替と返済を記録し、多通貨に対応した精算（誰が誰にいくら払えば清算できるか）を算出する。

| 提供面 | 内容 |
|---|---|
| iOS アプリ | 主な利用面。グループ作成、取引の記録、精算の確認 |
| Web（tateca.net） | LP と、グループの精算・取引履歴の閲覧（読み取り専用） |
| API | 本番 `https://api.tateca.net`、ステージング `https://staging-api.tateca.net` |

## ドメインの全体像

```
認証ユーザー ──1:N── メンバー（グループごとの表示名）──N:1── グループ
                                                          │ 1:N
                                                        取引（立替・返済）──1:N── 義務（各メンバーの負担額）

通貨 ──1:N── 為替レート（日付ごと）
```

| 概念 | 意味 |
|---|---|
| 認証ユーザー | Firebase 認証のアカウントに対応する、システム内のユーザー。UID で一意に識別される。初回ログイン時に作られ、ログイン記録とアプリレビュー設定を持つ |
| 要求者 | 操作を要求した、認証済みの利用者 |
| グループ | 共有費用を管理する単位。招待トークンでメンバーが参加する |
| メンバー | グループの構成員。グループごとに作られ、そのグループでの表示名を持つ（requirements では「ユーザー」とも呼ぶ）。参加済みメンバーと未参加メンバーがある。1人の認証ユーザーは、参加しているグループの数だけメンバーを持つ |
| 参加済みメンバー | 認証ユーザーと紐付いたメンバー。招待トークンでグループに参加した状態。requirements では「認証済みメンバー」とも呼ぶ |
| 未参加メンバー | 認証ユーザーと紐付いていないメンバー。名前だけで登録されたメンバーのほか、脱退したメンバーと、認証ユーザーが削除されたメンバーも未参加メンバーとして残る |
| グループサイズ上限 | 1つのグループに登録できるメンバー（参加済み・未参加の合計）の上限。値は group-member R3-AC1 で、作成時に指定できる参加者の数（作成者を除く）は group R2-AC5 で定める |
| 取引 | グループ内の費用の記録。「立替」（あるメンバーが支払い、他のメンバーが負担を分担する）と「返済」（あるメンバーが別のメンバーに借りを返す）の2種類 |
| 義務 | 1つの取引に対する、各メンバーの負担額 |
| 為替レート | 1 日本円あたりのその通貨の額（円が基準。例: 1 円 = 0.0067 米ドルなら 0.0067）。通貨と日付の組で1つに決まる。精算では、取引の金額をこの値で割って日本円に換算する。毎日自動で更新される |
| 通貨情報 | 通貨コード・日本語通貨名・英語通貨名・日本語国名・英語国名・通貨記号・記号位置を含む、通貨のメタデータ |
| 取引の日付 | 利用者が取引に指定する日時。取引に適用する為替レートは、この日時を UTC に直した日付のもの |
| 作成日時 | 取引がシステムに記録された日時。取引履歴の並び順に使い、取引を更新しても変わらない |
| Web 閲覧用のサービスアカウント | Tateca の Web（tateca.net）がサーバー側で使うアカウント。グループの精算・取引の閲覧に使う。読み取りだけが許され、変更はできない（transaction R22） |

## 共通の決まり

- **文字数**: 名前やタイトルの文字数は、UTF-16 の単位で数える。ひらがな・漢字・英数字は1文字、絵文字などは2文字以上として数えることがある

## 要件の一覧

| ドメイン | 文書 | 主な範囲 |
|---|---|---|
| アクセス制御 | `requirements/access.md` | すべての操作に共通する認証（利用者の操作と、内部システムの操作） |
| 認証ユーザー | `requirements/auth-user.md` | 認証ユーザーの作成・取得・削除、アプリレビュー設定の更新 |
| ユーザー | `requirements/user.md` | 表示名の更新 |
| グループ | `requirements/group.md` | グループの作成・取得・一覧・名前の更新、招待トークンによる参加、脱退 |
| グループメンバー | `requirements/group-member.md` | 未参加メンバーの追加・削除 |
| 取引 | `requirements/transaction.md` | 立替・返済の作成・取得・更新・削除、取引履歴、精算 |
| 為替レート | `requirements/exchange-rate.md` | 為替レートの取得、内部 API による毎日の更新 |

## requirements の書き方

- 1つのドメインにつき1つの文書を正本とする。
- AC には `R{n}-AC{m}` の ID を本文に書く（例: `R2-AC9`）。文書の外から参照するときは、ドメイン名を付けて `group R2-AC9` と書く。
- ID は一度振ったら変えない。新しい AC には次の番号を振り、削除した AC の番号は再利用しない。
- テストは、確かめた AC の ID を持つ。requirements とテストの対応は CI で確かめる。
- 要件や AC を変えるときは、PdM が承認する。
