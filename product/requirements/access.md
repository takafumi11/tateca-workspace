# Requirements Document — アクセス制御

## Introduction

Tateca は旅行・食事・イベントなど日常の割り勘シーンにおける共有費用を管理するアプリケーションである。
アクセス制御は、すべての操作に共通する「要求者の確認」を扱う。利用者向けの操作は、ログインした Firebase アカウントの認証情報で要求者を確認する。内部システム向けの操作は、API キーで要求者を確認する。

## Scope

- 利用者向けの操作における認証情報の確認
- 内部システム向けの操作における API キーの確認

### Out of Scope

- 操作ごとの権限（グループのメンバーであるか、自分自身のデータかなど）。それぞれのドメインの要件で扱う
- 認証アカウントそのものの作成・管理（Firebase 側の責務）

## Domain Definitions

- **利用者向けの操作:** 内部システム向けの操作以外のすべての業務操作
- **内部システム向けの操作:** 為替レートの更新
- **認証情報:** 利用者がログインした Firebase アカウントを証明する情報
- **API キー:** 内部システムだけが持つ鍵

## Requirements

### R1: 利用者の操作の認証

**User Story:** システム管理者として、認証されていないアクセスから利用者のデータを保護したい。

#### Acceptance Criteria

- **R1-AC1** GIVEN 利用者向けの操作である WHEN 認証情報を付けずに要求する THEN システム SHALL 認証が必要であるとして拒否する
- **R1-AC2** GIVEN 利用者向けの操作である WHEN 形式が不正な、または無効な認証情報で要求する THEN システム SHALL 認証が無効であるとして拒否する

### R2: 内部システムの操作の認証

**User Story:** システム管理者として、内部システム向けの操作を、内部システム以外から実行させたくない。

#### Acceptance Criteria

- **R2-AC1** GIVEN 内部システム向けの操作である WHEN API キーを付けずに、または誤った API キーで要求する THEN システム SHALL 認証が無効であるとして拒否する
