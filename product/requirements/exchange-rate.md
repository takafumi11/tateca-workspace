# Requirements Document — 為替レート

## Introduction

Tateca は旅行・食事・イベントなど日常の割り勘シーンにおける共有費用を管理するアプリケーションである。
為替レートは、各通貨の日本円に対する交換比率であり、取引の登録・確認や精算時の日本円換算に使われる。
この文書は、ユーザーが為替レートを参照する「為替レート取得」と、内部システムが為替レートを最新に保つ「為替レート更新」を扱う。

**為替レート取得:** ユーザーは取引の登録や確認時に、指定した日付の為替レート一覧を参照する。有効な通貨のレートのみが返却され、無効化された通貨のレートは除外される。

**為替レート更新（内部 API）:** 外部為替レートサービスから最新のレートを取得し、データベースに保存する内部操作である。この操作はスケジューラ（EventBridge + Lambda）によって毎日 UTC 00:01 に自動実行される。取得したレートは当日分と翌日分の 2 日分として保存され、翌日分は事前作成として機能する。

## Scope

### 為替レート取得

- 指定日付の有効通貨の為替レート一覧取得
- 為替レートが存在しない日付の場合は空の一覧を返却

### 為替レート更新（内部 API）

- 外部サービスからの最新為替レート取得
- 当日分と翌日分の為替レート保存（新規作成または更新）
- マスタデータに存在しない通貨のスキップ
- レートが変更されていない場合の更新スキップ（冪等性）

### Out of Scope

- ユーザーによる為替レートの作成・更新（内部 API でのみ行う）
- 特定通貨のみを指定した取得（常に全有効通貨を返却）
- 為替レートのキャッシュ
- 過去・未来の日付に対するアクセス制限（任意の日付を指定可能）
- 返却一覧の並び順の保証
- 更新時に特定日付を指定した為替レート取得（常に最新レートを取得）
- 為替レートの削除
- 外部サービスのリトライ制御（API クライアント層の責務）
- スケジューリング制御（EventBridge の責務）
- 外部サービスが返却する為替レート値の妥当性検証（0 や負の値の検証は行わない）

## Common Preconditions

- 為替レート取得（R1〜R2）: 要求者は認証済みである
- 為替レート更新（R3〜R7）: 要求者は API キーで認証済みである（内部システムからのアクセス）
- 認証されていない要求の扱いは `access.md` で定める

## Domain Definitions

- **為替レート:** ある通貨の日本円に対する交換比率。日付と通貨コードの組み合わせで一意に特定される
- **有効通貨:** システムで利用可能として登録されている通貨。無効化された通貨は為替レート取得から除外される
- **通貨情報:** 通貨コード・日本語通貨名・英語通貨名・日本語国名・英語国名・通貨記号・記号位置を含む通貨のメタデータ
- **通貨マスタ:** システムに登録されている通貨の一覧。外部サービスから取得したレートのうち、マスタに存在する通貨のみが保存対象となる
- **外部為替レートサービス:** 最新の為替レートを提供する外部 API
- **事前作成:** 翌日分のレートを前日に作成しておくこと。翌日の更新時に上書きされる

## Processing Order（為替レート更新）

1. 外部サービスから最新の為替レートを取得する
2. 当日日付で為替レートを保存する（既存の場合はレート変更時のみ更新）
3. 翌日日付で為替レートを保存する（既存の場合はレート変更時のみ更新）
4. 新規作成分を一括保存する（既存レートの更新は変更検知により自動反映）

## Requirements

### R1: 為替レート一覧の取得

**User Story:** 認証済みユーザーとして、特定の日付の為替レートを確認したい。取引に適切な為替レートを適用するため。

#### Acceptance Criteria

- **R1-AC1** GIVEN 指定された日付に有効通貨の為替レートが存在する WHEN 為替レート一覧の取得を要求する THEN システム SHALL 各通貨の為替レートと通貨情報を含む一覧を返却する

- **R1-AC2** GIVEN 指定された日付に為替レートが存在しない WHEN 為替レート一覧の取得を要求する THEN システム SHALL 空の一覧を返却する

- **R1-AC3** GIVEN 指定された日付において有効通貨と無効通貨の両方に為替レートが存在する WHEN 為替レート一覧の取得を要求する THEN システム SHALL 有効通貨のレートのみを返却する

### R2: 入力バリデーション

**User Story:** 認証済みユーザーとして、不正な入力に対して適切なエラーを受け取りたい。問題の原因を理解するため。

#### Acceptance Criteria

- **R2-AC1** GIVEN 認証済みユーザー WHEN 不正な形式の日付で為替レート一覧の取得を要求する THEN システム SHALL 入力不備として拒否する

### R3: 為替レートの新規保存

**User Story:** システム管理者として、最新の為替レートを自動的に取得・保存したい。ユーザーが最新のレートで取引を記録できるようにするため。

#### Acceptance Criteria

- **R3-AC1** GIVEN マスタデータに通貨が登録されており、当日および翌日の為替レートが存在しない WHEN 為替レート更新を実行する THEN システム SHALL 外部サービスから取得したレートを当日分と翌日分として保存する

- **R3-AC2** GIVEN 外部サービスが 3 通貨のレートを返却し、すべてがマスタに存在する WHEN 為替レート更新を実行する THEN システム SHALL 6 件（3 通貨 × 2 日分）のレコードを保存する

### R4: 既存レートの更新

**User Story:** システム管理者として、為替レートの変動をデータベースに反映したい。

#### Acceptance Criteria

- **R4-AC1** GIVEN 当日および翌日の為替レートが既に存在し、外部サービスが異なるレートを返却する WHEN 為替レート更新を実行する THEN システム SHALL 既存のレートを新しい値で更新する

- **R4-AC2** GIVEN 当日および翌日の為替レートが既に存在し、外部サービスが同じレートを返却する WHEN 為替レート更新を実行する THEN システム SHALL 更新をスキップする（更新日時も変更しない）

### R5: 未知通貨のスキップ

**User Story:** システム管理者として、マスタに登録されていない通貨のレートを無視したい。データの整合性を保つため。

#### Acceptance Criteria

- **R5-AC1** GIVEN 外部サービスがマスタに存在しない通貨のレートを含む WHEN 為替レート更新を実行する THEN システム SHALL 未知の通貨をスキップし、マスタに存在する通貨のレートのみを保存する

### R6: 外部サービス障害

**User Story:** システム管理者として、外部サービス障害時にデータの整合性を保ちたい。

#### Acceptance Criteria

- **R6-AC1** GIVEN 外部為替レートサービスが利用不可である WHEN 為替レート更新を実行する THEN システム SHALL エラーとして処理を中断し、データベースへの変更をロールバックする

### R7: 空レスポンスの処理

**User Story:** システム管理者として、外部サービスが空のレスポンスを返した場合でもシステムが正常に動作することを確認したい。

#### Acceptance Criteria

- **R7-AC1** GIVEN 外部サービスが空の為替レート一覧を返却する WHEN 為替レート更新を実行する THEN システム SHALL エラーを発生させず、保存件数として 0 を返却する
