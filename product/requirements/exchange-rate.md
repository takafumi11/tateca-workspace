# Requirements Document — 為替レート

## Introduction

Tateca は旅行・食事・イベントなど日常の割り勘シーンにおける共有費用を管理するアプリケーションである。
為替レートは、各通貨の日本円に対する交換比率であり、取引の登録・確認や精算時の日本円換算に使われる。
この文書は、ユーザーが為替レートを参照する「為替レート取得」と、内部システムが為替レートを最新に保つ「為替レート更新」を扱う。

**為替レート取得:** ユーザーは取引の登録や確認時に、指定した日付の為替レート一覧を参照する。有効な通貨のレートのみが返却され、無効化された通貨のレートは除外される。

**為替レート更新（内部 API）:** 外部為替レートサービスから最新のレートを取得し、当日分と翌日分の 2 日分として保存する内部操作である。内部システムが毎日自動で実行する。翌日分は事前作成として機能する。

## Scope

### 為替レート取得

- 指定日付の有効通貨の為替レート一覧取得
- 為替レートが存在しない日付の場合は空の一覧を返却

### 為替レート更新（内部 API）

- 外部サービスからの最新為替レート取得
- 当日分と翌日分の為替レート保存（新規作成または更新）
- マスタデータに存在しない通貨のスキップ
- 0以下のレートのスキップ
- 同じレートでの再実行（冪等性）

### Out of Scope

- ユーザーによる為替レートの作成・更新（内部 API でのみ行う）
- 特定通貨のみを指定した取得（常に全有効通貨を返却）
- 為替レートのキャッシュ
- 過去・未来の日付に対するアクセス制限（任意の日付を指定可能）
- 返却一覧の並び順の保証
- 更新時に特定日付を指定した為替レート取得（常に最新レートを取得）
- 為替レートの削除
- 外部サービス呼び出しの再試行
- 実行スケジュール

## Common Preconditions

- 為替レート取得（R1〜R2）: 要求者は認証済みである
- 為替レート更新（R3〜R8）: 要求者は API キーで認証済みである（内部システムからのアクセス）
- 認証されていない要求の扱いは `access.md` で定める

## Domain Definitions

- **為替レート:** 1 日本円あたりのその通貨の額（円が基準。例: 1 円 = 0.0067 米ドルなら 0.0067）。日付と通貨コードの組み合わせで一意に特定される
- **有効通貨:** システムで利用可能として登録されている通貨。無効化された通貨は為替レート取得から除外される
- **通貨情報:** 通貨コード・日本語通貨名・英語通貨名・日本語国名・英語国名・通貨記号・記号位置を含む通貨のメタデータ
- **通貨マスタ:** システムに登録されている通貨の一覧。外部サービスから取得したレートのうち、マスタに存在する通貨のみが保存対象となる
- **外部為替レートサービス:** 最新の為替レートを提供する外部 API
- **事前作成:** 翌日分のレートを前日に作成しておくこと。翌日の更新時に上書きされる
- **当日:** 為替レート更新を実行した時点の UTC の日付
- **翌日:** 当日の次の日（UTC の日付）

## Requirements

### R1: 為替レート一覧の取得

**User Story:** 認証済みユーザーとして、特定の日付の為替レートを確認したい。取引に適切な為替レートを適用するため。

#### Acceptance Criteria

- **R1-AC1** GIVEN 指定された日付に有効通貨の為替レートが存在する WHEN 為替レート一覧の取得を要求する THEN システム SHALL 各通貨の為替レートと通貨情報を含む一覧を返却する

- **R1-AC2** GIVEN 指定された日付に為替レートが存在しない WHEN 為替レート一覧の取得を要求する THEN システム SHALL 空の一覧を返却する

- **R1-AC3** GIVEN 指定された日付において有効通貨と無効通貨の両方に為替レートが存在する WHEN 為替レート一覧の取得を要求する THEN システム SHALL 有効通貨のレートのみを返却する

- **R1-AC4** GIVEN 指定された日付に、一部の有効通貨だけ為替レートが存在する WHEN 為替レート一覧の取得を要求する THEN システム SHALL 存在する通貨の為替レートだけを返却する

> 取引の登録・更新で代替の為替レートが保存された日付（`transaction.md` R3-AC2・R10-AC2）は、一部の通貨の為替レートだけを持つことがある。

### R2: 入力バリデーション

**User Story:** 認証済みユーザーとして、不正な入力に対して適切なエラーを受け取りたい。問題の原因を理解するため。

#### Acceptance Criteria

- **R2-AC1** GIVEN リクエスト入力が不正である WHEN 為替レート一覧の取得を要求する THEN システム SHALL 入力不備として拒否する

> 日付の形式は実装（コード）で定義する。

### R3: 為替レートの新規保存

**User Story:** システム管理者として、最新の為替レートを自動的に取得・保存したい。ユーザーが最新のレートで取引を記録できるようにするため。

#### Acceptance Criteria

- **R3-AC1** GIVEN 通貨マスタ（有効・無効を問わない）に通貨が登録されており、当日および翌日の為替レートが存在しない WHEN 為替レート更新を実行する THEN システム SHALL 外部サービスから取得したレートを当日分と翌日分として保存する

> R3-AC2（3通貨のレートを当日分と翌日分に1件ずつ保存する）は、R3-AC1 の具体例で新しいことを定めていなかったため欠番とする。

### R4: 既存レートの更新

**User Story:** システム管理者として、為替レートの変動をデータベースに反映したい。

#### Acceptance Criteria

- **R4-AC1** GIVEN 当日および翌日の為替レートが既に存在し、外部サービスが異なるレートを返却する WHEN 為替レート更新を実行する THEN システム SHALL 既存のレートを新しい値で更新する

- **R4-AC2** GIVEN 当日および翌日の為替レートが既に存在し、外部為替レートサービスが同じレートを返す WHEN 為替レート更新を実行する THEN システム SHALL 当日分と翌日分の為替レートを、通貨ごとに 1 件のまま同じ値で保つ

### R5: 未知通貨のスキップ

**User Story:** システム管理者として、マスタに登録されていない通貨のレートを無視したい。データの整合性を保つため。

#### Acceptance Criteria

- **R5-AC1** GIVEN 外部サービスがマスタに存在しない通貨のレートを含む WHEN 為替レート更新を実行する THEN システム SHALL 未知の通貨をスキップし、マスタに存在する通貨のレートのみを保存する

### R6: 外部サービス障害

**User Story:** システム管理者として、外部サービス障害時にデータの整合性を保ちたい。

#### Acceptance Criteria

- **R6-AC1** GIVEN 外部為替レートサービスが利用できない WHEN 為替レート更新を実行する THEN システム SHALL 外部サービス障害として失敗を返す

- **R6-AC2** GIVEN 外部為替レートサービスが利用できない WHEN 為替レート更新を実行する THEN システム SHALL 既存の為替レートを変えない

### R7: 空レスポンスの処理

**User Story:** システム管理者として、外部サービスが空のレスポンスを返した場合でもシステムが正常に動作することを確認したい。

#### Acceptance Criteria

- **R7-AC1** GIVEN 外部為替レートサービスが空の為替レート一覧を返す WHEN 為替レート更新を実行する THEN システム SHALL 失敗とせずに完了し、既存の為替レートを変えない

### R8: 0以下のレートの扱い

**User Story:** システム管理者として、外部サービスが誤って0以下のレートを返しても、保存済みの為替レートを壊したくない。精算では取引の金額を為替レートで割るため、0以下のレートが入ると精算できなくなる。

#### Acceptance Criteria

- **R8-AC1** GIVEN 外部為替レートサービスが、ある通貨のレートとして0以下の値を返す WHEN 為替レート更新を実行する THEN システム SHALL その通貨の為替レートを保存せず、既に保存されている為替レートも変えない
- **R8-AC2** GIVEN 外部為替レートサービスが、ある通貨には0以下の値を、ほかの通貨には正の値のレートを返す WHEN 為替レート更新を実行する THEN システム SHALL ほかの通貨の為替レートは通常どおり保存する
